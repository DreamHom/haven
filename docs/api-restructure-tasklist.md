# API restructure tasklist — clean up Scalar / OpenAPI surface

**Goal**: every endpoint in the [Scalar UI](http://localhost:8080/scalar.html) should
read like product copy, not autogenerated method names. Title, description,
example values, all error responses, security requirement — every piece.

This document is a working checklist. Tick boxes as endpoints land.

- [x] `/api` prefix stripped from displayed paths via `OpenApiCustomizer` (visual only — runtime routes unchanged).
- [x] JWT bearer security scheme declared (`bearerAuth`).
- [x] Personas documented in [`docs/users/`](users/) — every story below maps to one.

## The annotation pattern (template)

Every controller method should have this shape after restructuring. Use it
verbatim as the template — fill in the blanks per endpoint.

```java
@Operation(
    summary = "Short imperative phrase — 'Submit an offer on a listing'",
    description = """
        Longer prose describing what happens, when to call it, what side
        effects fire (notifications, outbox events, audit log writes), and
        any preconditions the caller must satisfy.
        """,
    tags = {"Offers"}  // matches a Tag declared in OpenApiConfig
)
@ApiResponses({
    @ApiResponse(
        responseCode = "201",
        description = "Offer created and PENDING.",
        content = @Content(
            mediaType = "application/json",
            schema = @Schema(implementation = OfferResponse.class),
            examples = @ExampleObject(name = "PendingOffer", value = """
                {
                  "id": 42,
                  "listingId": 17,
                  "applicantId": 89,
                  "amount": 7500000,
                  "status": "PENDING",
                  "submittedAt": "2026-05-10T08:30:00Z"
                }
                """)
        )
    ),
    @ApiResponse(responseCode = "400", description = "Validation failed.",
        content = @Content(schema = @Schema(implementation = ProblemDetail.class))),
    @ApiResponse(responseCode = "401", description = "Missing or expired JWT.",
        content = @Content(schema = @Schema(implementation = ProblemDetail.class))),
    @ApiResponse(responseCode = "403", description = "Listing not open for offers, or you're suspended.",
        content = @Content(schema = @Schema(implementation = ProblemDetail.class))),
    @ApiResponse(responseCode = "404", description = "Listing not found.",
        content = @Content(schema = @Schema(implementation = ProblemDetail.class))),
    @ApiResponse(responseCode = "409", description = "Listing already CLOSED, or another PENDING offer exists.",
        content = @Content(schema = @Schema(implementation = ProblemDetail.class)))
})
@SecurityRequirement(name = "bearerAuth")  // omit on public endpoints
@PostMapping(...)
public ResponseEntity<OfferResponse> submit(...) { ... }
```

For each endpoint we want:
- `@Operation` with clear `summary` + `description`.
- `@ApiResponses` listing **every** status code that can come back, each with a `ProblemDetail` schema reference (or the success DTO schema).
- At least one `@ExampleObject` on the success response.
- `@SecurityRequirement(name = "bearerAuth")` for authenticated endpoints (PUBLIC endpoints get an explicit `@SecurityRequirements({})` to opt out).
- Path / query / body params get `@Parameter` and `@Schema(example = ...)` annotations.

Class-level: every controller gets `@Tag(name = "...", description = "...")`.

## Cross-cutting tasks

These apply to every endpoint, do them in one sweep at the end:

- [ ] Every controller gets a class-level `@Tag(name = "...")` matching the OpenApiConfig declarations.
- [ ] Every authenticated endpoint gets `@SecurityRequirement(name = "bearerAuth")`.
- [ ] Every public endpoint gets `@SecurityRequirements({})` (explicit opt-out — clearer than absence).
- [ ] Standard error responses (`401`, `403`, `404`, `409`) declared via reusable `@ApiResponse` constants — consider an `OpenApiResponses` helper class with static @ApiResponse instances to avoid copy-pasting the same `ProblemDetail` schema reference everywhere.
- [ ] `ProblemDetail` (RFC 7807) schema appears in the components section so every error response can `$ref` it.
- [ ] All path / query / body params get `@Parameter` annotations with descriptions + examples.

## Execution order

I'd ship this in three PRs to keep the review surface manageable:

1. **PR: OpenAPI metadata + class-level tags** (foundation — already done in this branch).
2. **PR: Public-facing read endpoints** (Listings GET/browse, Photos GET, Slots GET, Comments GET, Reviews GETs, Users GET profile). These are the endpoints first-time visitors hit; they should look great in Scalar before authenticated ones.
3. **PR: Authenticated write endpoints** (Auth, Verifications, Inspections POST, Offers, Saves, Agent Assignments).
4. **PR: Admin endpoints** (smaller surface, can ship after).

Each PR runs `mvn verify` green; no behaviour changes; only annotations added.

## When this is done

Open `http://localhost:8080/scalar.html` after a clean rebuild. You should see:

- Sidebar grouped by tag (Auth, Users, Properties, …).
- Every endpoint with a clear summary, longer description, request body schema with example, response schemas (success + every error code).
- "Authorize" button at top — clicking it lets you paste a JWT once and have it apply across try-it-out calls.
- No `/api` prefix cluttering the path on every endpoint — it's hoisted into the server URL declaration.
